CSS Classes & Specificity

The Power of Targeted Styling

Up until now, we've styled our pages using element selectors like p, h1, or article. While element selectors work great for setting baseline styles, they have a major limitation: they style every single matching tag on the page.

What if you want one specific paragraph to be a highlighted alert callout, while leaving all other paragraphs alone? That's where CSS Classes come in.

Why Classes Are the Workhorse of Web Development

Classes give you surgical precision. Instead of forcing every <button> or <p> tag to look identical, classes allow you to create reusable style recipes that can be applied to any HTML element whenever you need them.

Class Syntax & Naming Conventions

Using a class requires two parts: assigning the class attribute in HTML, and selecting it with a dot (.) in CSS.

1. HTML Syntax: Add the class attribute to an element.

<p class="alert-box">This is an urgent message!</p>

2. CSS Syntax: Use a period (.) before the class name to target it.

.alert-box { background-color: #ef4444; color: white; }

Strict Naming Rules for Classes

  • No Spaces: Spaces in an HTML class attribute are used to separate multiple class names!
  • Use Kebab-Case: Use lowercase letters and separate words with hyphens (e.g., card-title, btn-primary, site-footer).
  • Do Not Start with Numbers: Class names should begin with a letter (e.g., use card-1 instead of 1-card).
  • Name by Purpose, Not Appearance: Choose names based on what the element is or does (e.g., .status-success instead of .green-text). If you change the design from green to blue later, .green-text won't make sense!

Multi-Class Magic: Combining Styles

HTML elements are not limited to just one class. You can apply multiple classes to a single tag by separating their names with spaces inside the class="" attribute!

buttons-example.html
HTML 
<!-- Base button structure + variant modifiers -->
<button class="btn btn-success">Save Changes</button>
<button class="btn btn-danger btn-large">Delete Account</button>

The Modular Component Pattern

Notice how .btn can handle shared baseline styles (padding, borders, border-radius), while .btn-success or .btn-danger handles the background color, and .btn-large handles text sizing. This keeps your CSS lean, reusable, and modular!

CSS Specificity: More Specific = More Important

When multiple CSS rules target the exact same element with conflicting styles, how does the browser decide which rule wins? It calculates a priority score called Specificity.

Think of specificity as a point system. The rule with the most specific target wins the tug-of-war:

CSS Specificity Hierarchy (Least to Most Specific)
Selector Type Example Specificity Level
Element Tag p { color: white; } Lowest Priority
Class Selector .highlight { color: yellow; } Medium Priority (Overrides Tags)
ID Selector #main-title { color: gold; } High Priority (Overrides Classes)
Inline Style Attribute style="color: red;" Highest Priority (Avoid Using!)

Inline Styles will be covered later in this course and IDs are covered in Web Development 2.

Rule 1: Classes Always Beat Tag Selectors

If you have p { color: white; } and .special { color: gold; }, any paragraph with class="special" will be gold because a class is more specific than a general HTML tag rule.

Rule 2: The Cascading Tie-Breaker

If two rules have the exact same specificity level (e.g., two class selectors targeting the same element), the last rule written in your CSS file wins. This is the "Cascading" nature of Cascading Style Sheets!

Chaining Selectors: Contextual Specificity

You don't always need to create a new class to target something specific. You can also increase priority and narrow down your styling targets by chaining selectors together (also known as descendant selectors).

When you separate tag names or class names with a space in CSS, you are telling the browser: "Only apply these styles if the rightmost element is nested inside all the elements that come before it."

chaining-example.css
CSS 
/* General Rule: Applies to ALL <strong> tags everywhere on the page */
strong {
    color: #f87171; /* Light Red */
}

/* Chained / Contextual Rule: Specific to nested elements */
p span strong {
    color: #38bdf8; /* Light Blue */
}

How Chaining Wins the Specificity Tug-of-War

Why does p span strong override the general strong rule?

  • strong has a specificity score of 1 tag.
  • p span strong has a specificity score of 3 tags combined (1 + 1 + 1).

Because 3 tags are more specific than 1 tag, p span strong gets higher priority! Furthermore, it restricts the blue color so it only applies to bold text inside a <span> that is sitting inside a <p> paragraph. A <strong> inside an <h1> or a <div> will remain red!

Chaining Classes with Tags

You can also chain classes together with tag selectors or other classes to target precise contexts without affecting other parts of your website:

  • .card h2 — Targets only <h2> headings that are inside an element with class="card".
  • article.featured (no space) — Targets <article> tags that specifically have the featured class attached directly to them.
  • .sidebar .btn — Targets buttons inside a sidebar section, ignoring buttons anywhere else on the page.

Classes vs. IDs: What's the Difference?

While an ID (e.g. #header) can also target elements, IDs are strictly unique—you can only use a specific ID once per HTML page. In contrast, classes can be used dozens or hundreds of times across the same document.

Best Practice: Use classes for almost all of your CSS styling. Save IDs primarily for JavaScript functionality and page anchor links!

Important: For this course, we will not be using IDs. IDs will be introduced in Web Development 2.

Putting It Together

In your web-1/learning/ folder, create a file named class-styles.html and link it to a stylesheet named classes.css.

class-styles.html
HTML 
<!DOCTYPE html>
<html lang="en">
<head>
    <title>Styling with Classes &amp; Chained Selectors</title>
    <link rel="stylesheet" href="classes.css">
</head>
<body>
    <main>
        <h1>Notification Center</h1>

        <p>General paragraph with standard <strong>red bold text</strong>.</p>

        <p>
            Paragraph containing a span with 
            <span><strong>contextual blue bold text</strong></span>!
        </p>

        <!-- Alert Banners using multi-class modular styling -->
        <div class="alert alert-info">
            <p>System update scheduled for midnight.</p>
        </div>

        <div class="alert alert-success">
            <p>Your project changes were saved successfully!</p>
        </div>

        <div class="alert alert-warning alert-large">
            <p>Warning: Storage limit is reaching capacity.</p>
        </div>
    </main>
</body>
</html>

Now style your alerts and nested elements inside classes.css:

classes.css
CSS 
/* Universal Reset */
* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

body {
    background-color: #0b1020;
    color: #e2e8f0;
    font-family: sans-serif;
    padding: 24px;
}

/* Base Tag Rule (Lowest Priority) */
strong {
    color: #f87171;
}

/* Chained Descendant Rule (3 Tags = Overrides 'strong' alone) */
p span strong {
    color: #38bdf8;
}

/* Tag Level Selector */
p {
    color: #94a3b8;
    font-size: 16px;
    margin-bottom: 12px;
}

/* 1. Base Class: Shared structure for ALL alerts */
.alert {
    padding: 16px;
    margin-bottom: 16px;
    border-left: 6px solid;
    border-radius: 4px;
    background-color: #1e293b;
}

/* Overriding element 'p' color specifically inside alerts */
.alert p {
    color: #ffffff;
    margin-bottom: 0;
}

/* 2. Modifier Classes: Color variants */
.alert-info {
    border-color: #38bdf8;
    background-color: #0f2b48;
}

.alert-success {
    border-color: #4ade80;
    background-color: #062d1b;
}

.alert-warning {
    border-color: #facc15;
    background-color: #3a2e05;
}

/* 3. Utility Modifier: Sizing variation */
.alert-large {
    padding: 28px;
}

Practice Exercise & Challenges

Put class flexibility, selector chaining, and specificity concepts to work by completing the following challenges:

  1. Experiment with Chained Overrides: In your class-styles.html, add a <div><p><strong>Test Text</strong></p></div> block. Write a chained selector in CSS (e.g., div p strong) that gives it a green background. Compare its priority against a simple strong selector in DevTools.
  2. Build a Badge Component: Create three <span> elements with class badge. Create modifier classes badge-primary, badge-secondary, and badge-outline to give each badge a unique color background and border.
  3. Test Specificity Overrides: Write a baseline rule in CSS targeting p with color: red;. Then write a class .text-custom with color: blue;. Apply the class to a paragraph. Which color wins in the browser? (Inspect the element in DevTools to see the red rule crossed out!).
  4. Create a Featured Card Modifier: Return to your fan-page.html file from earlier lessons. Write a chained selector .featured h2 to change only the title styling inside featured articles!
