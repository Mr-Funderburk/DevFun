Conditionals & Branching in Python

Branching refers to any point in a program where a decision alters the flow of execution. Computers make decisions by evaluating expressions into binary states: True or False (Boolean values).

Unlike human decisions, algorithm conditions must be concrete. An algorithm cannot evaluate a vague query like "Should I wear a jacket today?" until it is broken down into precise, measurable logic: temperature < 50.

The if Statement

In Python, the if keyword initiates a decision branch. If the expression evaluates to True, the indented code block directly below it executes. If it evaluates to False, Python completely skips that block.

conditionals.py
Python 
light_status = "On"

if light_status == "On":
    print("The room is illuminated.")

Syntax Checklist:

  • Keyword: Starts with the lower-case if keyword.
  • Comparison Operator: Uses == to check equality (distinct from single = assignment).
  • Colon: Ends with a colon (:) to declare the beginning of a code block.
  • Indentation: The body of the block must be indented (4 spaces).

Comparison Operators Quick Reference

Conditionals rely on relational operators to construct Boolean expressions. Given x = 5:

  • if x == 5: → True (Is equal to)
  • if x != 5: → False (Is not equal to)
  • if x > 5: → False (Greater than)
  • if x < 5: → False (Less than)
  • if x >= 5: → True (Greater than or equal to)
  • if x <= 5: → True (Less than or equal to)

The else Statement

When an if condition evaluates to False, Python skips its body. To create a fallback path that runs specifically when the condition fails, we attach an else block.

conditionals.py
Python 
light_status = "Off"

if light_status == "On":
    print("The room is illuminated.")
else:
    print("The room is dark.")

The else clause acts as a universal catch-all: it does not take a condition. It executes if and only if all preceding conditions in the chain evaluate to False.

Chaining Conditions with elif

When dealing with scenarios with more than two potential states, running multiple independent if statements forces the CPU to evaluate every single condition—even after finding a match.

Using elif (short for else if) creates a mutually exclusive chain. As soon as Python finds a condition that evaluates to True, it executes that body and bypasses all remaining checks in the structure.

conditionals.py
Python 
day = "Monday"

if day == "Saturday" or day == "Sunday":
    print("It's the weekend!")
elif day == "Monday":
    print("Back to school!")
elif day == "Friday":
    print("Almost the weekend!")
else:
    print("Midweek grind.")

Control Flow Structure Rules

When assembling complex branching logic, keep these strict structural rules in mind:

  • Required Opening: A branching structure must always begin with exactly one if statement.
  • Middle Chains: You may include zero or as many elif statements as necessary.
  • Optional Termination: You can include at most one else statement, and it must sit at the absolute end of the chain.

Complex Conditionals: Logical Operators

In real-world applications, decisions rarely depend on a single condition. A program often needs to evaluate multiple variables simultaneously—such as checking both a user's password and two-factor authentication code. Python provides three logical operators to combine or invert Boolean expressions: and, or, and not.

1. The and Operator

The and operator requires every individual condition to evaluate to True for the overall statement to be True. If even one condition fails, the entire statement evaluates to False.

conditionals.py
Python 
age = 16
has_permit = True

# Both conditions must be True to qualify
if age >= 16 and has_permit:
    print("Eligible for a driving test.")
else:
    print("Not eligible for a driving test.")

2. The or Operator

The or operator requires at least one condition to evaluate to True. The overall expression will only evaluate to False if every condition listed fails.

conditionals.py
Python 
day = "Saturday"

# Triggers if either condition evaluates to True
if day == "Saturday" or day == "Sunday":
    print("It's the weekend!")
else:
    print("It's a weekday.")

3. The not Operator

The not operator inverts (flips) the Boolean value of an expression. If a condition is True, applying not makes it False, and vice versa.

conditionals.py
Python 
is_logged_in = False

# Triggers if is_logged_in is False (not False -> True)
if not is_logged_in:
    print("Please log in to continue.")

Logical Operator Truth Table Summary:

  • True and True → True | All other and combinations are False.
  • False or False → False | All other or combinations are True.
  • not True → False | not False → True.

Working Directly with Boolean Variables

When a variable already holds a Boolean value (True or False), you do not need to explicitly compare it using == True or == False. Because an if statement automatically evaluates whether the expression after it is True, passing the Boolean variable by itself is sufficient.

Implicit vs. Explicit Checks

While both methods perform the exact same action, passing the variable directly is considered standard, clean Python style (often called Pythonic).

conditionals.py
Python 
is_logged_in = True

# Explicit Check (Redundant, but valid)
if is_logged_in == True:
    print("Welcome back!")

# Implicit Check (Clean / Pythonic)
if is_logged_in:
    print("Welcome back!")

Checking for False with not

Similarly, when testing if a Boolean variable is False, use the not operator instead of comparing to == False.

conditionals.py
Python 
game_over = False

# Explicit Check
if game_over == False:
    print("Keep playing!")

# Implicit Check using 'not'
if not game_over:
    print("Keep playing!")

Note for Beginners:

Using short hand like if x: or if not x: is optional. Writing if x == True: is completely valid syntax and will not cause your program to crash or error out. If spelling out == True helps you keep track of your logic while learning, feel free to use it! As you become more comfortable with Boolean expressions, using if x: will naturally become second nature.
