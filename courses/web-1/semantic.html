Semantic HTML & Structure

What Does "Semantic" Mean?

In linguistics, semantics is the study of meaning. In web development, semantic HTML tags are tags that clearly describe their meaning to both the browser and the developer.

For example, tags like <h1>, <p>, and <img> are semantic because they tell us what content is inside them. On the other hand, non-semantic tags say nothing about their content—they just act as generic containers.

Meaning Over Appearance

When you look at a web page in a browser, semantic structural tags (like <header> or <main>) don't look like anything special on their own. They don't add borders, colors, or fancy fonts automatically. So why use them?

Why Semantic Tags Matter

Even though semantic tags don't change how your page looks right away, they are essential for three major reasons:

  1. Accessibility (Screen Readers): Visually impaired users use screen readers to navigate web pages. Semantic tags act as landmarks, allowing screen readers to jump straight to the navigation menu, the main article, or the footer.
  2. Search Engine Optimization (SEO): Search engines like Google crawl web pages to understand what they are about. Semantic tags help search engines identify your page's primary content vs. secondary links or disclaimers.
  3. Code Readability & Organization: Working on team projects or reading your own code months later becomes much easier when layout sections are clearly labeled rather than being a confusing mess of generic blocks.

Understanding the Parent-Child Relationship

Before building a full layout, we need to talk about how elements relate to each other inside the Document Object Model (DOM) tree. Web page elements nest inside one another like Russian nesting dolls.

  • Parent Element: An element that contains other elements inside its opening and closing tags.
  • Child Element: An element direct inside another element.
  • Sibling Elements: Elements that share the exact same parent element.

Let's look at an example:

family-tree-example.html
HTML 
<article>
    <h2>Project Title</h2>
    <p>This is a short description of the project.</p>
</article>

Analyzing the Hierarchy

  • <article> is the parent to both <h2> and <p>.
  • <h2> and <p> are children of <article>.
  • <h2> and <p> are siblings to each other because they sit on the same nesting level inside the same parent.

Rule of Indentation: Whenever you place a child tag inside a parent tag, always indent it by pressing Tab (or 4 spaces). This visually shows the parent-child relationship in your code editor!

Core Structural Tags

Here are the fundamental semantic elements used to construct modern web pages:

  • <header> — Introductory content for a page or section, typically holding logos, main site titles, and navigation bar elements.
  • <nav> — Dedicated wrapper for primary navigation links.
  • <main> — Holds the central, unique content of the web page. There should only be one <main> tag per HTML page!
  • <article> — A self-contained, independent piece of content that could stand on its own (like a blog post, news article, or product card).
  • <footer> — Sits at the bottom of a page or section and contains copyright information, contact details, or secondary site links.

Check for Understanding: The Fan Page Challenge

It's time to build your first structured web page! You will create a single-page "Fan Page" dedicated to your favorite video game, movie, band, sport, or hobby.

In your web-1/learning/ folder, create a new file called fan-page.html. Your page must strictly follow the semantic layout structure shown below:

layout-wireframe.txt
Wireframe 
+-------------------------------------------------------+
|  HEADER: Site Title + Navigation (2 links)            |
+-------------------------------------------------------+
|  MAIN CONTENT:                                        |
|  +-------------------------------------------------+  |
|  | ARTICLE 1: Project Title + Image + Paragraph    |  |
|  +-------------------------------------------------+  |
|  +-------------------------------------------------+  |
|  | ARTICLE 2: Project Title + Image + Paragraph    |  |
|  +-------------------------------------------------+  |
+-------------------------------------------------------+
|  FOOTER: Copyright Notice                             |
+-------------------------------------------------------+

Project Requirements Checklist:

  1. Start with standard HTML boilerplate code (including doctype, html, head, title, and body tags).
  2. Header Section (<header>):
    • An <h1> tag displaying your Fan Page title.
    • A <nav> element containing at least two anchor links (<a> tags). One link should jump back to common-elements.html using a relative path, and the other can point to an external fan site using an absolute URL.
  3. Main Content Section (<main>):
    • Contains two distinct <article> tags as direct children.
    • Article 1: Must contain an <h2> title, an <img> (saved in your learning/images/ folder using a relative path and proper alt description), and a descriptive <p> paragraph.
    • Article 2: Must contain a second <h2> title, a second <img> tag, and a descriptive <p> paragraph.
  4. Footer Section (<footer>):
    • A copyright notice wrapped in a <p> or <small> tag (e.g., &copy; 2026 Fan Page Project).
  5. Code Formatting: Make sure all child elements are neatly indented inside their parent elements!
