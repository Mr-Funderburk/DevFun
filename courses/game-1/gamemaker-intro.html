Intro to GameMaker Engine

Navigating the GameMaker Interface

Welcome to digital game creation! GameMaker is a flexible engine capable of building top-tier 2D games (like Undertale, Hotline Miami, and Katana Zero). Every game engine relies on a Graphical User Interface (GUI)—the buttons, windows, and panels you interact with using your mouse and keyboard.

Before writing code or placing objects, let's break down the major sections of the default GameMaker layout:

GameMaker Interface Table
GUI Region Location Primary Purpose & Functions
Menu Bar Top Edge Contains drop-down menus for project management (File), undo/redo actions (Edit), and global engine settings.
Quick Toolbar Below Menu Bar Provides instant action buttons: Run (F5), Debug (F6), Stop, Clean, Game Options, and Zoom controls. Hover over any icon to see its tooltips and keybind shortcuts.
Inspector Panel Left Side Displays and edits properties for whichever asset or room item is currently selected.
Workspace Center Area The main canvas where visual code blocks, event windows, sprite editors, and room layouts open for editing.
Asset Browser Right Side The file cabinet for your game. Organizes all raw assets into folders (Sprites, Objects, Rooms, Sounds, Scripts).

Pro Tip: Customizing Workspace Layouts

Almost every dock panel in GameMaker can be expanded, collapsed, or detached. You can rebind hotkeys anytime via File > Preferences > Keybinds.

First Project: "Bomb Sweeper"

To put interface knowledge into practice, you will construct a fast-paced survival mini-game: bombs will spawn randomly around the screen, ticking down toward detonation. The player must move quickly to collect and defuse them before time runs out!

Step 1: Creating Game Sprites

Sprites are the 2D visual representations of entities in your game. At this stage, game developers use simple geometric shapes ("programmer art") to verify gameplay logic before drawing final art assets.

Naming Conventions Standards

To keep large projects organized, every asset type requires a consistent prefix:

  • Sprites: Prefix with spr (e.g., spr_player or spr_player)
  • Objects: Prefix with obj (e.g., obj_bomb or obj_bomb)
  • Rooms: Prefix with rm (e.g., rmLevel1 or rm_level1)

Formatting Style: camelCase vs. snake_case

You may use camelCase (e.g., sprPlayerShip) or snake_case (e.g., spr_player_ship). Pick one convention and stick to it consistently across your entire project! The examples and code segments given to you in this course will be snake_case.

Creating spr_player and spr_bomb

  1. In the Asset Browser (right panel), right-click and create a new Group called Sprites.
    Depending on your version, default groups may or may not already exist. If this group already exists, you can skip this step. The groups you create in the future will depend on your project and your preference. However, to begin, we will separate each of our game object types.
  2. Right-click the Sprites folder group and select Create > Sprite.
  3. Rename the sprite to spr_player in the top Inspector field.
  4. Change the resolution dimensions to 32 x 32 pixels.
  5. Click Edit Image to open the drawing editor. Use the circle/shape tool to fill a 32x32 colored shape (top-down view representation).
  6. Repeat this process to create a second sprite named spr_bomb (32x32 pixels, drawn in a distinct red or black color).

Step 2: Building Interactive Objects

While sprites are static images, Objects contain the logic, collisions, and instructions that bring games to life.

1. Player Object (obj_player)

  1. In the Asset Browser (right panel), right-click and create a new Group called Objects.
  2. Right-click the Objects folder > Create > Object. Name it obj_player.
  3. Assign spr_player as its active sprite in the Object Editor preview box.
  4. Click Add Event > Select Step > Step. (The Step event runs continuously on every single frame of the game—typically 60 times per second).
  5. GameMaker Studio supports both visual- and text-based coding. For this course, the examples will be done using the text-based code.
  6. Add the code below to the Step event.
obj_player > Step
GML 
if (keyboard_check(vk_left) || keyboard_check(ord("A"))) {  // left
	//x = x - 5;
	x -= 5;
}

if (keyboard_check(vk_right) || keyboard_check(ord("D"))) {  // right
	//x = x + 5;
	x += 5;
}

if (keyboard_check(vk_up) || keyboard_check(ord("W"))) {  // up
	//y = y - 5;
	y -= 5;
}

if (keyboard_check(vk_down) || keyboard_check(ord("S"))) {  // down
	//y = y + 5;
	y += 5;
}

Let's break down this code:

Lines 1, 6, 11, and 16 are all asking the question "Is this key pressed down on the keyboard?". If the answer is 'yes', then the code below the line executes (or runs). If the answer was no, the code below is skipped.

Each body of the if blocks have two code segments, one of which is commented out. They both do the same thing, with the non-commented line being a short-hand way to write the commented out line. It's up to you which method you like best. The important part is consistency! Pick a method and stick with it!

Take a minute to notice the syntax of the code here. The condition of the if statement is in parentheses (). The two pipes (|) mean or. Each if statement uses the curly braces {} to indicate what code belongs to that statement. Finally, each statement (or single line of code) ends with a semicolon (;)—kind of like how we end each sentence with a period to show we are done with that sentence.

2. Bomb Object (obj_bomb)

  1. Create a new object named obj_bomb and assign the spr_bomb sprite.
  2. Add Event > Create. Add the code below to create an Alarm (GameMaker's built-in timer).
obj_bomb > Create
GML 
alarm[0] = 60 * 5;
  1. Add Event > Alarm > Alarm 0 This event is what happens when the timer expires. Add the code below that will use GameMaker's built-in effects to create three explosions. Then, it will set a second timer.
obj_bomb > Alarm 0
GML 
effect_create_depth(depth, ef_explosion, x, y, 2, c_gray);
effect_create_depth(depth - 1, ef_explosion, x, y, 1, c_orange);
effect_create_depth(depth - 2, ef_explosion, x, y, 0, c_red);

alarm[1] = 15;

GameMaker Documentation

GameMaker has really good documentation which you can find here: GameMaker Documentation

Another way you can get to the documentation is to hold Ctrl or Cmd on the keyboard and the click on a function in GameMaker. This will take you to the documentation on that function. Try it with effect_create_depth().

Alternatively, you can click on top of a function and press F1 on your keyboard. (If you're on a laptop, you may need to hold the fn key as well.)

  1. Add Event > Alarm > Alarm 1 Use the code below to restart the game.
obj_bomb > Alarm 1
GML 
room_restart();
  1. Add Event > Collision > obj_player Use the code below to "defuse" the bomb (we're just going to destroy that instance of the object).
obj_bomb > Collision > obj_player
GML 
instance_destroy();

3. Spawner Object (obj_spawner)

  1. Create an object named obj_spawner. Leave its sprite unassigned (appears as a gray ?).
  2. Add Event > Create: Add code to set an alarm (Alarm 0) for 30 frames. See if you can do this without looking! Do you remember the code to set a new alarm?
  3. Add Event > Alarm > Alarm 0 When Alarm 0 goes off, we will create a new instance of obj_bomb and place it randomly on the screen.
obj_spawner > Alarm 0
GML 
// get a random place in the room and store in temporary variables
temp_x = irandom_range(64, room_width - 64);
temp_y = irandom_range(64, room_height - 64);

// create a new instance of obj_bomb
instance_create_layer(temp_x, temp_y, "Instances", obj_bomb);

// reset the timer so another bomb will spawn after a delay
alarm[0] = 180;

Step 3: Room Setup & Playtesting

  1. Double-click Room1 in the Asset Browser under the Rooms folder.
  2. Drag 1 instance of obj_player into the room viewport.
  3. Drag 1 instance of obj_spawner into the room viewport.
  4. Press F5 (or click the green Play button) to build and run your game! Test moving around to catch bombs before their fuse timers trigger an explosion restart.

Project Export Instructions

To submit your project for grading, export it as a compressed GameMaker project archive file (.yyz):

  1. Navigate to the top Menu Bar: File > Export Project > YYZ.
  2. Save the file using the naming convention: lastname-bomb-sweeper.yyz.
  3. Upload your completed .yyz file to the course assignment portal.
