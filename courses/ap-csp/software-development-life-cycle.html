The Software Development Life Cycle (SDLC)

Building high-quality computing innovations requires a structured process. The Software Development Life Cycle (SDLC) is a formal framework used by computer scientists and software engineers to design, build, test, and deliver reliable software applications. By following standard SDLC practices, development teams can meet user needs, prevent costly bugs, manage project budgets, and deliver software on schedule.

In computer science—and specifically on the AP Computer Science Principles exam—software development is recognized as an iterative and collaborative process. Programmers rarely follow a straight line from start to finish; instead, they refine their code continuously through feedback, testing, and documentation.

Phases of the Software Development Life Cycle

While different engineering organizations adapt the framework to fit their team size, most projects move through seven core phases:

1. Planning

In the planning phase, project managers and lead engineers establish the project scope, objectives, budget, timeline, and resource allocations. Planning establishes clear boundaries to prevent scope creep—the tendency for a project to continually expand beyond its original goals.

Planning involves collaboration with stakeholders—anyone who affects or is affected by the application. Stakeholders include end users, clients, software developers, domain experts, and business analysts.

2. Defining Requirements

Before designing a solution, engineers must define the program specifications. Requirements define both what the application must do and the constraints it must respect:

  • Functional Requirements: Features and behaviors the application must support (e.g., user authentication, search indexing, or data filtering).
  • Resource & Platform Requirements: Hardware requirements, operating system compatibility, network bandwidth constraints, and required external software libraries.

3. Design & Prototyping

The design phase determines how the software will meet its requirements without writing final production code. Key elements include:

  • System Architecture: Selecting programming languages, frameworks, data structures, and overall system design patterns.
  • User Interface (UI) & User Experience (UX): Designing layout mockups and defining how users interact with the program and receive output.
  • Security & Communication Protocols: Establishing data encryption standards (SSL/TLS), password hashing, and network protocols.
  • Prototyping: Constructing early, simplified models of the system to gather user feedback before investing heavy development time.

4. Software Development & Documentation

Developers write the source code based on the design specifications. For team projects, programmers use Version Control Systems (VCS) like Git to track changes, manage parallel feature branches, resolve code conflicts, and review code collaboratively.

AP CSP Essential Knowledge: Program Documentation

Documentation is an essential part of software development. It explains how program logic works and how users should interact with the software. Program documentation includes:

  • Inline Code Comments: Explanations within source code describing algorithm logic, variable purposes, and function parameters. Comments improve code readability and facilitate maintenance.
  • User Guides & APIs: Written technical specifications, onboarding tours, and API documentation for external developers.

5. Testing & Quality Assurance

Before software reaches users, it must be thoroughly tested to identify logic errors, performance bottlenecks, and security vulnerabilities. Testing involves evaluating various input conditions:

  • Normal Cases: Typical inputs expected during standard usage.
  • Edge / Boundary Cases: Inputs at the absolute minimum, maximum, or extreme limits of expected values (e.g., testing empty inputs, zero, or max integer values).
  • Invalid / Unexpected Inputs: Testing how the program handles improper data types or malicious input without crashing (robustness).

6. Deployment

In deployment, the completed software is delivered to end users. Deployment can range from automated app store updates and web cloud deployment to complex multi-server infrastructure database migrations.

7. Operations & Maintenance

Once deployed, software enters maintenance. Users discover bugs that slipped through quality testing, hardware/OS platforms update, or new user requirements emerge. Customer feedback in the maintenance phase triggers new development cycles for future software patches and feature updates.

SDLC Methodologies & Models

Different software engineering projects require different workflows. SDLC models dictate how a team transitions through planning, coding, and testing phases.

1. Waterfall Model

The Waterfall model is a strict, sequential workflow. Each phase must be 100% completed, reviewed, and approved before the next phase begins. While easy to manage for small projects with rigid, unchanging requirements, Waterfall makes it difficult and costly to make changes once coding has started.

2. Agile Methodology

The Agile methodology prioritizes flexibility, customer feedback, and continuous delivery. Instead of releasing software all at once, Agile breaks development into short cycles called sprints (typically 1 to 4 weeks). Each sprint produces a functional increment of the software that is tested and reviewed by stakeholders, allowing developers to adapt quickly to changing user needs.

3. Iterative & Incremental Development

In an Iterative model, developers build a simplified working version of the program first. With each iteration, engineers add features (incremental updates) and refine existing code based on testing and user evaluations until the final system is built.

4. DevOps

DevOps (Development + Operations) integrates software development teams with system administration/operations teams. By automating software building, testing, and continuous deployment (CI/CD pipelines), DevOps reduces time-to-market and improves software stability in production environments.

5. Lean Development

Adapted from lean manufacturing principles, Lean software development focuses on efficiency by eliminating wasteful practices (e.g., redundant code, unnecessary documentation, delays), optimizing team learning, and delivering user value quickly.

Conclusion Questions

Answer the following questions to demonstrate your mastery of software development practices, testing strategies, and project management methodologies.

  1. Why is software development defined in AP Computer Science Principles as an iterative process? Explain how user feedback influences software design throughout the development lifecycle.
  2. Compare and contrast the Waterfall model and the Agile framework. In what specific project scenarios would a team select Waterfall over Agile?
  3. A programmer writes code to calculate a student's final percentage grade (0-100%). List three specific test inputs the programmer should use to thoroughly evaluate the program: one normal case, one boundary/edge case, and one invalid case.
  4. Explain why inline code comments and official program documentation are crucial during team-based software development and post-deployment maintenance.
  5. What is the purpose of constructing a software prototype during the design phase? Why is catching design flaws during prototyping far less costly than fixing them during development or deployment?
