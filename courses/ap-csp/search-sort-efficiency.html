Searching, Sorting, & Algorithmic Efficiency

Understand how computers locate and organize data, evaluate search strategies, and measure algorithmic performance using Big-O notation.

1. Searching Algorithms

Searching is one of the most fundamental operations in computer science. Given a dataset and a target value, a search algorithm determines whether the target exists in the dataset and returns its location (index).

A. Linear Search (Sequential Search)

Linear Search starts at the very beginning of a collection (index 0) and inspects every item one by one in sequential order until it finds the target or reaches the end of the collection.

  • Requirement: Works on any dataset (sorted or unsorted).
  • Worst-Case Steps: If the list has N items, Linear Search may need up to N checks.

B. Binary Search

Binary Search uses a divide-and-conquer strategy. It inspects the middle element of a collection. If the middle element is larger than the target, the algorithm discards the entire upper half. If it's smaller, it discards the lower half. It repeats this halving process until the target is located.

  • Requirement: Data MUST BE SORTED beforehand! Binary Search will fail on unsorted data.
  • Worst-Case Steps: Every check cuts the search space in half. For N items, it takes at most log2(N) steps.

# Linear Search Implementation
def linear_search(data, target):
    for i in range(len(data)):
        if data[i] == target:
            return i  # Return index position where target was found
    return -1  # Target not found

# Binary Search Implementation (Requires sorted data!)
def binary_search(data, target):
    low = 0
    high = len(data) - 1
    
    while low <= high:
        mid = (low + high) // 2
        if data[mid] == target:
            return mid  # Found!
        elif data[mid] < target:
            low = mid + 1  # Discard lower half
        else:
            high = mid - 1  # Discard upper half
            
    return -1  # Target not found

2. Introduction to Sorting Methods

Because fast search algorithms like Binary Search require sorted data, organizing datasets efficiently is a core problem in software engineering. Sorting algorithms rearrange elements into ascending or descending order.

AP CSP Course Requirement Note

You are expected to understand how all sorting algorithms below work conceptually (especially the Divide and Conquer strategy). However, on exams and assignments, you will only be asked to trace or write simpler sorts like Bubble or Selection. You will NOT be required to write Merge Sort or Quick Sort code from memory.

A. Simple / Iterative Sorts

  • Bubble Sort: Iteratively steps through the list, compares adjacent elements, and swaps them if they are in the wrong order. Larger elements "bubble" to the end of the list with each pass.
    Show Bubble Sort Python code
    bubble_sort.py
    Python 
    def bubble_sort(values):
    n = len(values)
    for end in range(n - 1, 0, -1):
        swapped = False
        for i in range(end):
            if values[i] > values[i + 1]:
                values[i], values[i + 1] = values[i + 1], values[i]
                swapped = True
        if not swapped:
            break
    return values
  • Selection Sort: Divides the array into a sorted and unsorted region. Repeatedly scans the unsorted region to find the minimum element and swaps it into its correct position at the front.
    Show Selection Sort Python code
    selection_sort.py
    Python 
    def selection_sort(values):
    for start in range(len(values)):
        min_index = start
        for i in range(start + 1, len(values)):
            if values[i] < values[min_index]:
                min_index = i
        values[start], values[min_index] = values[min_index], values[start]
    return values
  • Insertion Sort: Builds the sorted array one element at a time. Takes the next unsorted item and inserts it into its proper position relative to the elements already sorted (like sorting a hand of playing cards).
    Show Insertion Sort Python code
    insertion_sort.py
    Python 
    def insertion_sort(values):
    for i in range(1, len(values)):
        current = values[i]
        position = i - 1
        while position >= 0 and values[position] > current:
            values[position + 1] = values[position]
            position -= 1
        values[position + 1] = current
    return values

B. Divide & Conquer / Recursive Sorts

  • Merge Sort: A classic Divide and Conquer algorithm. Recursively splits the unsorted dataset in half until individual elements remain, then repeatedly merges the smaller sorted sub-lists back together in correct order.
    Show Merge Sort Python code
    merge_sort.py
    Python 
    def merge_sort(values):
    if len(values) <= 1:
        return values

    middle = len(values) // 2
    left = merge_sort(values[:middle])
    right = merge_sort(values[middle:])
    merged = []
    left_index = right_index = 0

    while left_index < len(left) and right_index < len(right):
        if left[left_index] <= right[right_index]:
            merged.append(left[left_index])
            left_index += 1
        else:
            merged.append(right[right_index])
            right_index += 1

    merged.extend(left[left_index:])
    merged.extend(right[right_index:])
    return merged
  • Quick Sort: Selects a "pivot" element from the array and partitions the remaining elements into two sub-arrays (those smaller than the pivot and those larger). Recursively sorts the sub-arrays.
    Show Quick Sort Python code
    quick_sort.py
    Python 
    def quick_sort(values):
    if len(values) <= 1:
        return values

    pivot = values[-1]
    smaller = [value for value in values[:-1] if value <= pivot]
    larger = [value for value in values[:-1] if value > pivot]
    return quick_sort(smaller) + [pivot] + quick_sort(larger)

3. Algorithmic Efficiency & Big-O Notation

How do computer scientists measure whether one algorithm is "better" than another? We do not measure raw execution speed in seconds, because a fast supercomputer will always run code faster than a smartphone. Instead, we measure algorithmic efficiency by counting the number of computational steps required as the input size (N) grows.

Big-O Notation describes the upper bound (worst-case scenario) of an algorithm's growth rate:

Big-O Table
Big-O Complexity Name Description & Example
O(1) Constant Time Execution steps remain identical regardless of input size N. (e.g., Accessing list item by index lst[0]).
O(log N) Logarithmic Time Steps grow slowly because input size is halved each step. (e.g., Binary Search).
O(N) Linear Time Steps grow proportionally 1-to-1 with input size N. (e.g., Linear Search).
O(N log N) Log-Linear Time Optimal efficiency for general comparison sorting algorithms. (e.g., Merge Sort, Quick Sort).
O(N2) Quadratic Time Steps grow exponentially when using nested loops over dataset N. (e.g., Bubble, Selection, Insertion Sorts).
Grading vs. Conceptual Knowledge

In this course, your lab Python code is graded on correctness and logical design rather than execution efficiency. However, for AP CSP assessments, you must understand how algorithms are measured and be able to compare execution steps as datasets scale from 10 items to 1,000,000 items!

Reasonable Time: An algorithm whose execution time grows polynomial-style (N, N2, N3). Linear (O(N)) and Binary (log2(N)) searches run in reasonable time.

Unreasonable Time: An algorithm whose execution time grows exponentially (2N or N!). As the list size grows slightly, execution time explodes, making it impossible to solve on modern hardware for large inputs.

Algorithm Comparison Summary

Algorithm Comparison Table
Algorithm Type Worst-Case Efficiency Prerequisite Requirement
Linear Search Search O(N) None (works on unsorted data)
Binary Search Search O(log N) Dataset must be sorted!
Bubble / Selection / Insertion Sort O(N2) None
Merge / Quick Sort Sort O(N log N) Divide & Conquer methodology

Trade-off Analysis:

Sorting an unsorted list takes time (O(N log N)).

When Linear Search is better: If you are only doing a single search on a small or frequently changing list, sorting first is wasteful.

When Binary Search is better: If you sort the dataset once and perform thousands/millions of lookups over time (like a user login system), Binary Search is exponentially faster.
