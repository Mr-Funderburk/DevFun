Demystifying the Web

Demonstration

Go to any popular website like YouTube, Wikipedia, or TIME. Then right-click on the web page and select Inspect. This allows us to see the Document Object Model (DOM) tree and we can edit the page locally. Change one of the headlines to something like "Canterbury Declares Every Friday a Free Pizza Day!"

The Web Isn't Solid Stone

It's just text documents sending instructions to a browser. Today, you start writing those instructions.

Your Workbench

Before writing a single tag, we need to establish our root folder for the course. This will help with the majority of broken images and dead links while we're getting started.

Golden Rules of Web Files:

  1. Everything lives inside a dedicated class folder (e.g., web-dev-1).
  2. NO SPACES or special characters in file/folder names (use hyphens: my-first-site).
  3. Everything must be lowercase.
  4. The main entry page of any project is always named index.html.

On your Desktop or in your Documents (your choice), create a new folder called web-1. Every file you create or use for this class should reside in this folder!

Create a new folder inside of this web-1 folder called learning. We will start in this folder, just creating some basic pages to help you learn. Then we will branch out to other projects which will have their own folders.

Integrated Development Environment (IDE)

While web development doesn't need a dedicated program to create web pages, it certainly helps! You could create all of your web pages using any text editor that comes with your Operating System (OS). (This is the way I started!) However, times have changed and there are a lot of free editors out there that can help with productivity while making your web pages.

The one I'm going to suggest for this course is VS Code. It's a light weight, modular code editor that will serve well for HTML and CSS editing. However, you're welcome to use a plain text editor, Sublime Text, Notepad++, or any other editor you'd like for this course.

Boilerplate / Bare-Bones

All of our web pages will start out the same. So let's create an example and talk about what's happening. Start by creating a new file in the learning folder we just created. Let's call it boilerplate.html. Note the extension: .html. Be sure you write that as well. A file extension tells your system what type of file it is and how it should be handled. In this case, we're telling our system that it will be a Hypertext Markup Language document (the one that builds a web page). Without this extension, your computer will probably just treat it as a standard text document and will not be able to be seen by your browser.

Add the following code to your page, save it, and then open it in your web browser (or VS Code's Integrated Browser).

boilerplate.html
HTML 
<!DOCTYPE html>
<html lang="en">
<head>
    <title>My First Web Page</title>
</head>
<body>
    <h1>Hello, World!</h1>
    <p>My name is [Student Name] and I am building a website from scratch.</p>
</body>
</html>

Congratulations! You just created your first web page!

So What's Going On Here?

  • <!DOCTYPE html> is telling the browser (the program you use to view web pages, like Chrome, Edge, Firefox, or Safari), that this page contains markup for HTML 5.
  • <html> is the parent wrapper holding everying.
  • <head> is information about the page (invisible information like metadata, style, script, and font links, and the title of your page).
  • <body> is everything the user actually sees on the screen.

Elements & Tags

All of the elements (paragraphs, images, headers, etc.) on our page are created using tags. It's important to understand the anatomy of a tag as you will be writing a lot of them in this class!

Every tag starts with a less than sign (<), then the name of the element, and finally a greater than sign (>). Most tags require a closing tag as well which is written the exact same, only has a forward slash (/) before the element name.

Most HTML tags work like a set of bookends. Always remember to close what you open!

Let's look at the h1 element we used in our boilerplate. The h1 element is the largest heading. The convention is for each page to have one and only one of these. This should be the main heading of the page and tell the user, "what is the page about?" The h1 tag then is formed with the less than sign, the name h1, and then a greater than sign. The closing tag is exactly the same with the forward slash before the h1. Between the open and closing tags of the h1 is what we want the heading to say. The paragraph (p) element is formed the same way.

Nesting Elements

Elements can exist inside of other elements as well. For example, we can create a paragraph, then decide that we want some of the words inside that paragraph to be bold. To accomplish this, we will add a strong tag before the word(s) we want to be bold and then close the strong tag when we're done. Try making your name bold.

Make sure you close tags in the reverse order that they are opened! <p>my <strong>AWESOME</strong> paragraph</p>

Breaking It

Unlike coding languages, HTML doesn't show error screens—the browser just tries its best to guess what you meant. This can make debugging tricky.

Try deleting a closing tag, misspell a tag (boddy instead of body), or move some text outside of the closing body tag. What happens?

Nothing! (Mostly) So take a deep breath and don't fear errors or mistakes!

Code Formatting

HTML treats multiples spaces as a single space and doesn't require any formatting to work. However, look at the next two examples and tell me which code you would rather work with:

boilerplate.html
HTML 
<!DOCTYPE html>
<html lang="en">
<head>
    <title>My First Web Page</title>
</head>
<body>
    <h1>Hello, World!</h1>
    <p>My name is [Student Name] and I am building a website from scratch.</p>
</body>
</html>

OR

boilerplate.html
HTML 
<!DOCTYPE html><html lang="en"><head><title>My First Web Page</title></head><body><h1>Hello, World!</h1><p>My name is [Student Name] and I am building a website from scratch.</p></body></html>

Both files will run exactly the same. However, updating and working on the second would be a nightmare!

Therefore, you will be asked to keep your code formatted correctly. Indentation shows ownership of elements. Notice how we indent the h1 element because it belongs to the body element. Try to keep your code as neat and tidy as you can. These indentations can help you find issues in your page!
